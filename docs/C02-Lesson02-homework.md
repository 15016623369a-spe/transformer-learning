## 第一题：六个概念

| 问题 | 答案 |
|---|---|
| 为什么需要位置信息？ | 相同 Token 单纯查表得到相同向量，向量本身没有显式表示当前位置。本课加上可学习绝对位置向量，使后续计算可以使用位置信息。 |
| Q、K、V 各做什么？ | Query 与 Key 用于计算匹配分数，Value 是最后按权重汇总的信息。Self-Attention 中三者来自同一份输入，但经过不同的线性变换。 |
| 为什么 Q 与 K 维度相同而 Value 可以不同？ | Q 与 K 做点积，其特征数必须一致。权重是在 Key 位置之间分配，再对相应 Value 加权，因此 Value 的特征数 d_v 不必等于 d_k。 |
| scores[b,i,j] 表示什么？ | 第 b 条输入中，Query 位置 i 与 Key 位置 j 的缩放匹配分数；不是最终概率。 |
| 为什么 Softmax 沿最后一维？ | 最后一维是 Key 位置，对每个固定 Query，需要在所有允许的 Key 之间归一化。 |
| 两类 Mask 分别限制什么？ | Padding Mask 禁止从补齐 Key 读取信息；Causal Mask 禁止读取当前 Query 之后的未来位置。PAD Query 的最终输出本课另行清零。 |

## 第二题：第二个 Query 的手算

Q 的第二行是 `[0,1]`，与三个 Key `[1,0]`、`[0,1]`、`[1,1]` 的点积分数为：

```text
[0,1,1]
```

d_k=2，除以 sqrt(2)：

```text
[0,0.70710678,0.70710678]
```

第二个 Query 的位置下标为 1，因果限制禁止读取位置 2：

```text
[0,0.70710678,-∞]
```

权重约为：

```text
[0.33023845,0.66976155,0]
```

对 Value 加权：

```text
0.33023845 × [2,0]
+ 0.66976155 × [0,4]
+ 0 × [6,6]
= [0.66047690,2.67904620]
```

脚本的 `run_manual_exercise()` 打印完整矩阵，并使用独立的指数公式核对第二行，而不是仅把同一行代码运行两遍。

三位小数显示的完整权重与输出：

```text
weights = [[1.000,0.000,0.000],
           [0.330,0.670,0.000],
           [0.248,0.248,0.503]]

output  = [[2.000,0.000],
           [0.660,2.679],
           [3.517,4.014]]
```

显示小数存在舍入，不应根据显示结果要求每行恰好相加为 1.000；代码用浮点容差检查。

## 第四题：三个错误实验

### 1. 禁止位置填成 0

```python
bad = scores.masked_fill(~allowed, 0.0)
bad_weights = torch.softmax(bad, dim=-1)
```

因为 exp(0)=1，禁止位置仍有非零权重。本次教师样例中，禁止位置最大权重约为 0.276391，且权重逐行和仍为 1。只检查行和不足以证明 Mask 正确。

修正是在 Softmax 之前填入负无穷，并单独检查被禁止位置的权重为零。

### 2. Softmax 改成 dim=-2

对于 [B,Query位置,Key位置]，-2 是 Query 维度。它在一列的不同 Query 之间归一化，不符合每个 Query 对 Key 分配权重的要求。

本次第一条输入的 PAD 列全是 -∞，沿该列计算 Softmax 还会产生 NaN。第二条没有 PAD，虽然有限，逐行和约为 `[0.244,0.651,1.384,1.721]`，仍然不正确。无 PAD 时不一定产生 NaN，但归一化方向仍然错误。

修正为 `torch.softmax(masked_scores, dim=-1)`。

### 3. 整条输入全部为 PAD

所有 Key 都被禁止，手工 Softmax 的整行输入为 -∞，没有可归一化的允许位置，直接计算得到 NaN。

新增 `masked_attention()` 在 Softmax 前检查每行是否存在可读 Key，不存在则抛出清晰的 ValueError。本次作业选择明确拒绝这样的输入；不把 NaN 事后填零当作正确计算。

错误实验有意展示 NaN，并捕获预期拒绝；正常教师流程和第三题输出仍通过有限数值检查。
